## Goal

大哥从一个**每 30 分钟被叫醒、把全部事实重读一遍、把结论倒进收件箱的派工中间人**，变成一个**持续在线、按事件驱动、只把需要你拍板的事交给你的常驻助理**：环境变化成为一等 Trigger；名单外的噪音在进模型前就被程序层滤掉；已建立的线由程序直通负责会话，不再需要大哥每轮复述上下文；产出有结构性上界，因而收件箱能收敛而不是只靠人工清理；大哥上岗之前先有一条能说清「你不在的这段时间发生了什么」的恢复路径。

全部差距按基线规格 §4 的 G-01 ~ G-11 收敛，验收以基线规格 §7 的六道闸门为准。**收工时，`node --test` 全绿且条数不少于 602（2026-11-01 基线），四道守卫脚本全绿，发布副本与仓库逐字节一致。**

## Phases

### Phase 1 · 让大哥能安全上岗

> 对应缺口 **G-10**；对应闸门 **Gate 5**。这一步是**「大哥重新上岗」的前置**，不是并行项。
> **状态：已落地**（提交 `bca89e9` + `docs(plan)` 一批；详见 [`progress.md`](progress.md) 的 Phase 1 收尾块）。

- [x] 1.1 空档的补齐策略写成显式代码：**一趟覆盖整段尚未覆盖的空档**（补状态，不逐槽重放）——*原方案是「采样代表槽位」，读代码后改掉，见 [`findings.md`](findings.md) F1.1*
- [x] 1.2 空档时长**如实上报**：摘要里写清「断了多久」，不用槽位数代替时间
- [x] 1.3 覆盖标记**可前进**（不再锁死），且按需重新覆盖是**显式动作**、不是自愈：`patrol-cli gap reset "<理由>"`
- [x] 1.4 产出「上岗摘要」：给**大老板**看的一段话，说清断了多久、算漏班几轮、还欠几轮
- [x] 1.5 变异验证：六个新检查逐个改坏，确认**每个都会变红**（含补一个专抓 `coverable` 冗余项的用例）

**动手时补上的三条根因**（原计划没预见，见 [`findings.md`](findings.md) F1.4）：

- [x] 1.6 覆盖标记是死的 → 心跳整条链路只能补一次 → 改成记「覆盖到第几槽」
- [x] 1.7 补位失败被记成「已补」→ 永不重试 → 失败不推进覆盖标记
- [x] 1.8 心跳从不读值班意图 → 休息期间照样被派值班轮次 → `resting` 不补位，休息期的空槽不算漏班

**退出证据：** 大老板给出「大哥，上岗」，恢复的不是「从上次继续」，而是一份说清断档期的摘要；且断档期里休息的那部分**不会被当成漏班**。

### Phase 2 · 事实层：Trigger 与两级过滤

> 对应缺口 **G-02**、**G-03**；对应闸门 **Gate 1**。**这是所有东西的地基**——没有 Trigger，订阅、直通、链式召回、投机执行都无处挂。

- [ ] 2.1 定义 Trigger 契约（纯函数）：类型 / 来源 / 时间 / 主体 / 摘要 / 引用 ID
- [ ] 2.2 接入四类事件源：项目状态变化、新问卷卡、会话异常、cron 唤醒
- [ ] 2.3 Fast Path（程序层确定性准入）：管辖名单匹配 + 事件类型白名单
- [ ] 2.4 `facts` 改为双段输出：`raw`（只读全量，默认**不**给模型）+ `candidates`（程序筛后）
- [ ] 2.5 语义层（Slow Path）留在提示词里，作为可随时扩展的策略点
- [ ] 2.6 变异验证：塞一条**名单外**的事件，断言它**进不了** `candidates`；再塞一条名单内的，断言它**能**进

**退出证据：** 事件源可枚举；Fast Path 有会失败的断言；一轮巡检进模型的上下文体积**可测量地下降**。

---

### Phase 3 · 直通：Thread 与订阅

> 对应缺口 **G-04**、**G-05**；对应闸门 **Gate 2**。这一层是「主动」这个特征真正的来源。

- [ ] 3.1 Thread 抽象：**一个管辖项目 = 一条 Thread**，其项目根会话为负责方
- [ ] 3.2 订阅状态：Thread → 负责会话，可查、可撤销
- [ ] 3.3 直通投递：同一 Thread 的后续事件**由程序直接送负责会话**，不经大哥重新分派
- [ ] 3.4 降级路径：直通失败退回「大哥重新分派」，并记一次降级（不静默）
- [ ] 3.5 Inline & Spill：`facts` 分层（摘要 + ID + 按需展开），长内容截断留续读入口
- [ ] 3.6 链式召回短程版：从当前事件沿引用图逐跳展开
- [ ] 3.7 越权闸：直通**永远不越过管辖名单**——名单外的线直通不了

**退出证据：** 派工后，同一线的新事件不经大哥直接进负责会话，有端到端证据。

---

### Phase 4 · 产出收敛与低打扰

> 对应缺口 **G-11**；对应闸门 **Gate 1.5**。**用户立刻能感到的一步**——收件箱从 93 条未确认收敛到有上界。

- [ ] 4.1 结论分级：只有「**需要你拍板**」的进收件箱，其余进可查的流水
- [ ] 4.2 同类合并 + 幂等：已报过的不重复报（`alreadyReported` 升级为**结构性**保证，不是提示词约定）
- [ ] 4.3 带宽纪律：单条结论 ≤ 100 词（抄文章 §4.2 的 IM 硬规矩），固化为断言
- [ ] 4.4 历史 93 条**归档不删除**（结论有历史价值），归档动作本身要留痕
- [ ] 4.5 技能匹配接进派工路径，让 `skill-library.json` 的 `usageCount` **不再是 0**

**退出证据：** 「需要你拍板」的条目数有结构性上界；技能匹配被真实触发过至少一次。

---

### Phase 5 · 线视角的板面

> 对应缺口 **G-01**；对应闸门 **Gate 3**。文章 A2/A3 的直接落地：**Session 不该是用户的认知负担**。

- [ ] 5.1 定义「线」：一个管辖项目 + 大哥在这条线上的作为 + 待你决策的事
- [ ] 5.2 总览页改版：我的一个大哥 / N 条线 / K 件等你拍板
- [ ] 5.3 线的状态卡：进度 / 最近动作 / 下一步 / **是否在等你**
- [ ] 5.4 事件流视图（Thread 视角）：看得到「这条线最近发生了什么」
- [ ] 5.5 旧的按项目总览**保留为下钻层**，不做第二套总览

**退出证据：** 板面上「需要你拍板」的条目不超过一个屏幕；线视图能回答「哪条线卡住了」。

---

### Phase 6 · 韧性：判进展、全双工、状态收口

> 对应缺口 **G-09**、**G-07**、**G-08**；对应闸门 **Gate 4**。三个缺口互不依赖，可以并行推进，但合成一个阶段验收。

- [ ] 6.1 「实质进展」纯函数判据：产出增长 / 状态迁移 / 新产物
- [ ] 6.2 看门狗把 **stale（心跳旧）与 stuck（有会话在跑但无进展）分开报**
- [ ] 6.3 值班轮次改异步语义（`start` / `stop`）：后台跑的同时能接新指令，新指令**不排队等轮次结束**
- [ ] 6.4 状态收口：板面状态从散落的多个 json 收到一个带版本与原子写的 store

**退出证据：** 造一个「进程活着但无实质进展」的场景，看门狗**必须**报 stuck。

## 开放决策（等大老板拍板，不阻塞开工）

以下三项**不阻塞** Phase 1 / Phase 2 的开工，但**在对应阶段开始前必须有答案**：

| # | 决策 | 阻塞 | 本计划里的默认（若未拍板就按这个走） |
| --- | --- | --- | --- |
| D1 | 大哥重新上岗的时间点与恢复范围 | Phase 1 的验收 | 采样补齐 + 如实上报断档时长 |
| D2 | 板面「线」的信息架构细节（线 = 项目还是更细的粒度） | Phase 5 | 线 = 一个管辖项目（与 Thread 一一对应） |
| D3 | 收件箱上界是硬条数还是「需要拍板」语义 | Phase 4 | 语义上界 + 可配置条数兜底 |

> 按大老板的常驻授权（决策不阻塞）：① 目标明确、验收清晰、风险可逆 → 直接做并写明理由；② 有歧义但影响面小 → 选最贴合原目标的方案，写明放弃了什么；③ 不可逆 / 跨项目冲突 / 需求本质变更 → 才停下来上报。

## 不在本计划范围内

| 项 | 为什么 |
| --- | --- |
| 云端无状态计算 + 数据库存状态 | 基线规格 §5 否决清单：我们的持久性瓶颈是「宿主进程会停」，不是「设备多」 |
| 端侧轻量 daemon（BYOM） | 同上：只有一台机器，执行环境就是它自己 |
| IM / GitHub 多信道接入 | 只有两个本地入口；带宽纪律照搬，接入方式不照搬 |
| Router 层水平切分 / sharding | 量级不匹配；且短程记忆都没稳，切分会提前丢掉连续性 |
| 跨实例 A2A | 管辖名单已经划好边界，多实例需求不存在 |
| 模型与系统协同设计（Co-design）训练 | 我们不训模型 |
| 跨月长程记忆 | 文章自己列为开放问题；先做链式召回的短程版 |
| 目标创建能力出口 | 主规格 §26 已记录（宿主有、我们没有出口），属独立议题，不混进本计划 |

## 贯穿全程的门

1. **测试**：`node --test` 全绿，且条数**不少于** 602（2026-11-01 基线，602 项全绿）。
2. **守卫**：`check-published` / `check-package` / `check-style` / `verify-agent-notes` 四道全绿。
3. **变异验证**：任何新写的检查或门禁，交付前必须**先证明它会失败**——故意改坏被保护的东西，确认退出码非零且报错点名，再改回来。
4. **单一写路径**：所有写操作仍走 `ProjectService`；运行时库仍**只读**。
5. **提交纪律**：路径限定提交，不用 `git add -A` / `git add .` / `git commit -a`。改动走 PR，**Squash and merge**。
6. **发布副本**：源码改完必须逐字节同步到 `~/.minimax/plugins/mimic-tear/`，并复核到 0 处不一致。
