## Goal

大哥从一个**每 30 分钟被叫醒、把全部事实重读一遍、把结论倒进收件箱的派工中间人**，变成一个**持续在线、按事件驱动、只把需要你拍板的事交给你的常驻助理**：环境变化成为一等 Trigger；名单外的噪音在进模型前就被程序层滤掉；已建立的线由程序直通负责会话，不再需要大哥每轮复述上下文；产出有结构性上界，因而收件箱能收敛而不是只靠人工清理；大哥上岗之前先有一条能说清「你不在的这段时间发生了什么」的恢复路径。

全部差距按基线规格 §4 的 G-01 ~ G-11 收敛，验收以基线规格 §7 的六道闸门为准。**收工时，`node --test` 全绿且条数不少于 602（2026-11-01 基线），四道守卫脚本全绿，发布副本与仓库逐字节一致。**

**动手时补上的三条根因**（原计划没预见，见 [`findings.md`](findings.md) F1.4）：

- [x] 1.7 补位失败被记成「已补」→ 永不重试 → 失败不推进覆盖标记
- [x] 1.8 心跳从不读值班意图 → 休息期间照样被派值班轮次 → `resting` 不补位，休息期的空槽不算漏班

**退出证据：** 大老板给出「大哥，上岗」，恢复的不是「从上次继续」，而是一份说清断档期的摘要；且断档期里休息的那部分**不会被当成漏班**。

- [x] 2.2 接入四类事件源：项目状态变化、新问卷卡、会话异常、cron 唤醒

- [x] 2.6 变异验证：塞一条**名单外**的事件，断言它**进不了** `candidates`；再塞一条名单内的，断言它**能**进

- [x] 2.9 「管辖区外的不给看」与「要看得见全世界」的冲突 → 拆成 `candidates` / `raw` 两个视图（F2.5）

**退出证据：** 事件源可枚举 ✓；Fast Path 有会失败的断言 ✓（8 个变异逐个改坏，全部变红）；一轮巡检进模型的上下文体积**可测量地下降** ✓（真实数据 85,540 → 59,265 字节，**-30.7%**）。

### Phase 3 · 直通：Thread 与订阅

> 对应缺口 **G-04**（G-05「上下文组织」拆到 Phase 3b，见下）；对应闸门 **Gate 2**。
> **状态：已落地（能力），闸门待验收**（提交 `5f711e7`；详见 [`progress.md`](progress.md) 的 Phase 3 收尾块）。

- [x] 3.1 Thread 抽象：**一个管辖项目 = 一条 Thread**，负责方是它的根会话（F3.1）
- [x] 3.2 订阅状态：`thread-subscriptions.json`，Thread → 负责会话，可查可撤销（F3.2）
- [x] 3.3 直通投递：`context.agent.run({ sessionId, text, whenBusy: 'queue' })` —— **不经大哥**（F3.1）
- [x] 3.4 降级路径：投递失败的**不记账** → 事件还在 → 下一轮自然接住（F3.5）
- [x] 3.5 ~~Inline & Spill~~ → **拆到 Phase 3b**（G-05 是另一件事：上下文组织，不是路由）
- [x] 3.6 ~~链式召回短程版~~ → **拆到 Phase 3b**
- [x] 3.7 越权闸：订阅只在**管辖名单内**成立；名单外的项目即使有订阅项也不投（F3.2）

**这一阶段的三条硬结论**（写进了代码，不只在文档里）：

- **投递口比管辖权更窄**：两个都成立，直通才发生（F3.2）。
- **「已投出」是账，「已执行」是事实**：排队 ≠ 执行，订阅表记的是「已投出」（F3.3）。
- **直通默认关**（`patrol-config.json` 的 `directDelivery`）：它和大哥的值班轮次做同一件事，
  同时开就是同一份活干两遍。打开的前提是**提示词先改**（F3.4）。

**退出证据：** 派工后，同一线的新事件不经大哥直接进负责会话，有端到端证据。

> **闸门待验收的理由**：直通的投递口虽然从宿主文档确认了（`app.asar` 里的官方参考），
> 但**还没有一次真实的成功投递**。默认关就是为了让这件事在真实验证之前不产生任何行为。
> 验收需要：开一条订阅 → 造一个事件 → 看到它出现在项目会话里（而不是大哥的上下文里）。

### Phase 3b · 上下文组织：Inline & Spill + 链式召回

> 对应缺口 **G-05**；对应闸门 **Gate 1.7**（本阶段新立，见基线规格 §7）。
> **状态：pending**（小节先立，退出证据先定，再动手）。
>
> **它为什么从 Phase 3 里拆出来**：Inline & Spill 与链式召回是**上下文**的事（把有限的窗口当
> Cache 管），不是**路由**的事（谁负责哪条线）。两件事混在一个阶段里，验收标准会互相干扰。

- [x] 3b.1 给事实表里的内容项定**稳定 ID**（结论 / 会话 / 问卷 / 项目 / 目标 / 计划任务），跨轮次不变
- [x] 3b.2 **Inline & Spill**：长文本内联为「摘要 + 长度 + 续读入口」，超出的部分 Spill 到窗口之外
- [x] 3b.3 **链式召回（短程版）**：每个对象内联**下一跳的 ID 与摘要**，构成一张引用图
- [x] 3b.4 **续读入口**：按 ID 取回完整内容（`patrol-cli recall <id>`）
- [x] 3b.5 候选视图里带上引用图（下一跳 ID），并把 Spill 出去的项标出来
- [x] 3b.6 变异验证：故意改坏引用图 / 摘要 / 续读入口，确认**每个都会变红**

**退出证据（四条，全部拿到）：**

1. **跨线可召回** ✓ —— 真实数据上 `patrol-cli recall patrol_mvufn62m_62h8wq` 取回了那条结论，
   并给出链：**结论 → 它所在的线（Mimic Tear）**。
2. **Spill 出去的东西不丢** ✓ —— 取回的原文与原文**逐字一致**（单测断言 `=== long`）。
3. **上下文体积可测量地下降** ✓ —— 候选视图 **59,265 → 58,009 字节**。
   （中途踩过一个坑：先把整张引用图塞进负载 → **80,638 字节**，比不 Spill 还大。
   文章的设计是**图住在系统里、上下文里只内联下一跳的 ID**——见 F3b.2。）
4. **变异验证通过** ✓ —— 5 个变异逐个改坏，全部变红（M1 不截断 / M2 例外清单失效 /
   M3 链不跟随下一跳 / M4 跳数上限失效 / M5 续读入口不给原文）。

**本阶段顺手发现的一件事**：存储层**早就把标题截断到 120 字**了——那里已经有一次 Spill。
真正长的字段是**备注**与**运行时项的正文**。所以 Spill 的收益集中在那里，不是标题。

**不在本阶段范围内：**

- **跨月的长程记忆** —— 基线规格 §5 已明确搁置（文章自己也是开放问题）。本阶段只做**短程**链式召回。
- **模型侧的记忆压缩** —— 我们不训模型、不改模型的上下文策略；我们只管**我们注入什么**。
- **板面的呈现改版** —— 那是 Phase 5（G-01）。本阶段只管事实表的**形状**。

## 不在本计划范围内

| 项 | 为什么 |
| --- | --- |
| 云端无状态计算 + 数据库存状态 | 基线规格 §5 否决清单：我们的持久性瓶颈是「宿主进程会停」，不是「设备多」 |
| 端侧轻量 daemon（BYOM） | 同上：只有一台机器，执行环境就是它自己 |
| IM / GitHub 多信道接入 | 只有两个本地入口；带宽纪律照搬，接入方式不照搬 |
| Router 层水平切分 / sharding | 量级不匹配；且短程记忆都没稳，切分会提前丢掉连续性 |
| 跨实例 A2A | 管辖名单已经划好边界，多实例需求不存在 |
| 模型与系统协同设计（Co-design）训练 | 我们不训模型 |
| 跨月长程记忆 | 文章自己列为开放问题；先做链式召回的短程版 |
| 目标创建能力出口 | 主规格 §26 已记录（宿主有、我们没有出口），属独立议题，不混进本计划 |

## 贯穿全程的门

1. **测试**：`node --test` 全绿，且条数**不少于** 602（2026-11-01 基线，602 项全绿）。
2. **守卫**：`check-published` / `check-package` / `check-style` / `verify-agent-notes` 四道全绿。
3. **变异验证**：任何新写的检查或门禁，交付前必须**先证明它会失败**——故意改坏被保护的东西，确认退出码非零且报错点名，再改回来。
4. **单一写路径**：所有写操作仍走 `ProjectService`；运行时库仍**只读**。
5. **提交纪律**：路径限定提交，不用 `git add -A` / `git add .` / `git commit -a`。改动走 PR，**Squash and merge**。
6. **发布副本**：源码改完必须逐字节同步到 `~/.minimax/plugins/mimic-tear/`，并复核到 0 处不一致。
