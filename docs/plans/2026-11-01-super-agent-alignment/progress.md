### Phase 1 收尾块

**这一阶段修掉的三处根因**（都不是「缺个功能」，是「结构错了」）：

| # | 根因 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | 覆盖标记记的是「刚补的那一槽」，而空档起点恒等于「最后一次投递之后的第一格」 | 心跳整条链路**只能补一次** | 记「覆盖到第几槽」；覆盖标记随空档推进而推进 |
| 2 | 补位失败被写进状态（`lastTriggeredSlot = 那一槽`） | 那一段**永不重试** | 失败**不推进**覆盖标记 |
| 3 | 心跳**从不读**值班意图 | 被交代去休息的大哥照样被派值班轮次（只是被 #1 的锁碰巧挡住） | `resting` 不补位；休息期攒下的空槽不算漏班 |

**变异验证（6 个新检查逐个改坏）** —— 全部**变红**：

| 变异 | 改坏的东西 | 结果 |
| --- | --- | --- |
| M1 | `coverable` 去掉 `onDuty` 项 | 第一次**没抓住** → 补了专测用例（休息中 + 上岗前断链）后抓住 |
| M2 | 心跳不再尊重 `resting` | 红 ✅ |
| M3 | 覆盖标记不再前进 | 红 ✅ |
| M4 | 失败那轮也算已覆盖 | 红 ✅ |
| M5 | `gap reset` 不再清覆盖标记 | 红 ✅ |
| M6 | 空档分界失效 | 红 ✅ |

> M1 是这次唯一一次「变异没被抓住」：它暴露 `coverable` 的 `onDuty` 项在当前路径上是**冗余**的（休息时边界过滤已经把槽位清空）。补的用例覆盖「休息中 + 上岗前就断了链」这个边界场景，之后再变异就红了。**「一直通过的检查」和「没有检查」在结果上无法区分**——这条纪律救了一次。

**新加的判定口径**（都写进了代码注释，不只在文档里）：

- **洞 vs 漏班**：空档分成两段。`hole` = 宿主一共没触发多少轮；`gap` = 其中落在当前值班周期里的那部分。休息期间攒下的空槽**不算漏班**（「休息不是故障」，主规格 §27.6）。
- **断多久用时间说**，不用槽位数代替——219 轮和「4 天 14 小时」是同一件事，但只有后者能让人判断「这阵子没看着」有多要紧。
- **补的是当前状态，不是重放**——这句话同时进了**提示词**和**摘要**：不说的话，大哥会把「断了四个小时」汇报成「普通迟到」。

—— 大哥在休息、值班会话没在跑，**不误报** ✓。

**变异验证**：3 处逐个改坏 → 红 → 还原 → 绿（永远不判 stuck / 看门狗不认 stuck / 卡住解除后不重新武装）。

**6.3 值班轮次的异步语义（`start` / `stop`）—— 已落地（提交 `0d81f3c`）。**

**先纠正计划里原先的判断**：写这条时以为「值班轮次跑在独立会话里，所以新指令本来就不排队」，
这只对了一半。真正的问题在**板面这一侧**：大哥只有**一条**会话，巡检轮次、派工、跟大老板说话
全都跑在它上面；而宿主在会话正忙时对新的 `agent.run` **直接拒绝**（`BUSY` / `session_busy`）——
**没有轮次登记的地方，「大哥正忙着」等于「大老板说的话丢了」**。

三个动作都落地了：

- **start**：轮次是后台的（`POST /api/patrol/run` 返回 202 + `roundId`），同一槽位上重复启动
  **直接跳过**（不排第二遍）。
- **stop**：每条轮次带一个 `AbortController`；`POST /api/patrol/round/:id/stop` 叫停。
  **被叫停的轮次不算结论**（没跑完，产出不可信），但**留痕**：状态是 `aborted`，页面看得见。
- **新指令不排队等轮次结束**：会话正忙时按**在跑的是哪一类轮次**决定——
  **全是巡检轮次**（只读事实、不改文件）→ `steer`（插话进去，不排队等它跑完，回复由那一轮给出）；
  **只要有一轮可能是对话或派工**（可能在改文件）→ `queue`（排队，不切人家改到一半的东西）。

**证据**：新增 16 条测试（`tests/round-control.test.mjs` 10 条 + `tests/duty-round-async.test.mjs` 6 条），
逐条钉住上面三个动作；全量 724 项全绿。客户端的「巡检」按钮在轮次跑着时变成「叫停」，
页面重开会把在跑的轮次读回来（否则按钮回到「巡检」，叫停的入口就没了）。

### 收口之后保住的两个性质

**一条坏账只坏它自己。** 收口之前，派工账坏了不会让「代答」记不进去（那两条路写的是不同的文件）。
收口到一个文件之后这个性质得**显式保住**：一段账读不出来时，store 把它**标记为读不出来**
（而不是当成空段）——读那一段报错，别的段照常读写。

**过渡期老文件还写一份镜像（`abbec47`）。** 盯盘方给的退出证据里有一条「过渡期内旧文件仍可读」。
只做「迁移读一次、之后再也不被读」的话，老文件就是**陈旧快照**——万一这套收口后来被否掉、
回退到旧代码，旧代码读到的是迁移那一刻的数据，**回退等于丢数据**。所以 store 每次改动的那几段
会**镜像**回老文件：**真相只有 store 一份**（代码读的一直是 store，老文件只写不读），镜像是**派生
出来的**，给回退用。回退前还可以显式跑一次 `patrol-cli export-legacy` 把老文件补齐——
**回退是显式动作，不是自愈**。线上真跑过一次 `export-legacy`：8 个老文件全部写回，内容与 store
逐段一致。

### Gate 2 为什么不成立（宿主的能力边界）

投递链路本身**全通**：管辖闸过了、类型闸过了、归属闸过了、订阅在册、直通开关是开的——**唯一挡住的是最后一跳：投递口够不到目标会话。**

宿主 `MiniAppAgentClient.run/answer` 的所有权闸（`Saved/asar2/…/miniapp/agent/gateway.js:631-649`）规定：Mini App **只能续自己拥有的会话**（`owner !== caller.pluginId` → `SESSION_NOT_FOUND`）。宿主官方文档同一句约束：「each Mini App can only continue its own sessions」；读权限（`session.read`）是宽的，写权限是窄的。

而 Mimic Tear 的负责会话 `mvs_45d3d440…` 是**桌面端用户会话**（`purpose=null`、无 `miniAppOrigin`）→ **不是 Mini App 拥有的** → 直通投不进去。16 次调用全被 `SESSION_NOT_FOUND` 拒。

**唯一合法的落点**：让负责会话成为 **Mini App 自己拥有的会话**（照 `BossBridge` 已有的 `agent.run({ text, agent })` 建会话模式）。代价是这条线的产出**不再回到大老板当前这个窗口**，而是回到板面/那个会话——这与 Super-agent 的 Worker 隔离是一致的，但**改变了「负责会话」的取得方式，需要大老板拍板**。详见 `.agents/notes/proposed/architecture/`。
