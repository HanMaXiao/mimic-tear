# 仿身泪滴看板 · 视觉改版规范（值夜台 2.0）

> 2026-10-30 · 分支 `redesign/board-modern-ui`
>
> 这一版**只动视觉**：视图、路由、数据、按钮、字段一个不增不减。
> 改的是「怎么长」，不是「有什么」。

---

## 0. 改版前的诊断（基于现有代码）

现有设计**不是通用模板**——它已经有明确的两个语域、单一强调色、系统字体纪律。
所以这一版不是推翻重做，是把一套好想法推到「顶级」标准。真正的硬伤有七处：

| # | 问题 | 在哪儿 | 为什么是硬伤 |
|---|---|---|---|
| 1 | **排版层级是平的** | h1 17 / h2 14 / h3 13.5 / 正文 14 | 全站只有 3px 的字号差，页面没有主次。品牌名与正文几乎同重 |
| 2 | **明暗两套主题的机器界面冷暖相反** | 亮色 `#f0eee8`（暖）↔ 暗色 `#0a0d10`（冷） | 同一套「机器」在两种主题下换了温度，等于两套设计 |
| 3 | **纯平，零纹理** | 全部面板只有 1px 描边 | 大面积纯色块没有材质与景深，界面像线框图 |
| 4 | **加载态只有转圈** | `.spinner`（4 处） | 页面高度在数据到达前跳一下，且转圈不描述「在等什么」 |
| 5 | **数字排版不统一** | 只有 `.mono` / `.numeric` 有 tabular | KPI、计数、徽标、表格里的数字各用各的字形，列对不齐 |
| 6 | **没有跳过导航** | 无 skip link | 键盘用户第一下 Tab 要穿过 6 个导航项才到正文 |
| 7 | **间距是散落的 px** | 18/16/16、26/32/44、22/20… | 没有刻度，改一处就要手工对齐另外三处 |

## 1. 色彩方案

### 1.1 原则：两个语域，两种材质，各自有固定温度

```
CONSOLE（机器界面）  冷中性   ——  仪表、表格、树、计数
PAPER（文书界面）    暖       ——  交班报告、决策条目、派工单
```

**关键决定：纸永远是纸。** 亮色与暗色两套主题里，`--mcode-paper-*` 都保持暖调——
一张纸在夜里也不会变成蓝的。反过来，机器界面在两套主题里都是冷的。

这样修掉了诊断 #2：不再有「同一个语域在两个主题下温度相反」。

### 1.4 强调色纪律

**只有一个强调色**（`--mcode-accent`），一个信号色（`--mcode-lamp`），
三个语义色（好 / 注意 / 坏）。语义色**只花在状态上**，不用于装饰。

饱和度一律压在 80% 以下，让它们和灰阶相处，而不是尖叫。

### 1.5 景深（三级）

阴影带背景色相，不用纯黑透明：

```
--mcode-elev-1   0 1px 2px rgb(10 13 17 / 34%)                                   面板
--mcode-elev-2   0 2px 8px rgb(10 13 17 / 36%), 0 14px 32px rgb(10 13 17 / 30%)   浮起
--mcode-elev-3   0 10px 24px rgb(10 13 17 / 42%), 0 36px 72px rgb(10 13 17 / 40%)  对话框 / 提示
```

### 1.6 纹理

全屏一层 3.5% 的噪点（`feTurbulence`），`pointer-events: none`。
它不改变任何东西的颜色，只是让大面积纯色不再是「数字的」。

## 2. 排版规范

### 2.1 字体（不引入远程资源）

```
--mcode-console   'Bahnschrift SemiCondensed', 'Bahnschrift', 'DIN Alternate', 'Arial Narrow', …
--mcode-ui        'Microsoft YaHei UI', 'PingFang SC', 'Source Han Sans SC', 'Noto Sans CJK SC', …
--mcode-document  'Songti SC', 'STSong', 'FangSong', 'STFangsong', 'SimSun', serif
--mcode-mono      'Cascadia Mono', 'JetBrains Mono', ui-monospace, …
```

- **console**：仪表与编号（DIN 气质，窄、像设备刻度）
- **ui**：一切界面文字
- **document**：纸面上的散文（交班报告、决策正文）
- **mono**：路径、命令、原始标识

### 2.2 字号刻度

| 角色 | 字号 / 行高 | 字重 | 字距 | 用在哪 |
|---|---|---|---|---|
| display | 22 / 27 | 600 | -0.015em | 品牌名 |
| title | 19 / 26 | 600 | -0.01em | 页头视图名 |
| section | 15 / 23 | 600 | 0 | 区块标题 |
| body | 14 / 1.65 | 400 | 0 | 正文 |
| body-strong | 14 / 1.65 | 500 | 0 | 强调正文 |
| caption | 12 / 18 | 400 | 0.01em | 次要说明 |
| micro | 10.5 / 15 | 500 | 0.14em | 编号、eyebrow、徽标 |
| data | — | 600 | -0.01em | 数字（tabular-nums） |
| doc | 15 / 1.95 | 400 | 0.01em | 纸面散文（宋体） |

**规则**

- 标题一律 `text-wrap: balance`；正文 `text-wrap: pretty`（避免孤字）。
- **所有数字**（KPI、计数、徽标、表格数字、时间）统一 `font-variant-numeric: tabular-nums`，
  数字列因此天然对齐。
- 层级靠**字重 + 明度 + 间距**三层拉开，不靠加粗一种手段。

## 3. 间距 / 圆角 / 动效

### 3.1 间距刻度

```
--mcode-space-1: 4px    --mcode-space-5: 24px
--mcode-space-2: 8px    --mcode-space-6: 32px
--mcode-space-3: 12px   --mcode-space-7: 48px
--mcode-space-4: 16px
```

所有内边距、外边距、间隙都从这里取，**不再出现孤立的 px**。

### 3.2 圆角

```
--mcode-radius-xs: 4px     标签 / 内嵌小件
--mcode-radius-sm: 7px     控件（按钮、输入框）
--mcode-radius-md: 10px    卡片 / 指标块
--mcode-radius-lg: 14px    面板 / 对话框
--mcode-radius-pill: 999px 药丸（只在需要胶囊语义时用）
```

### 3.3 动效

```
--mcode-dur-fast: 120ms    悬停、按下
--mcode-dur: 200ms         状态切换
--mcode-dur-slow: 340ms    入场
--mcode-ease: cubic-bezier(0.22, 0.61, 0.36, 1)
--mcode-spring: cubic-bezier(0.34, 1.36, 0.64, 1)   回弹，用于浮起与选中
```

- 视图入场：父级淡入上移，子项**依次错开 40ms**（不是整块一起出现）。
- 按钮：悬停 `translateY(-1px)` + 边线提亮；按下 `translateY(0) scale(0.99)`。
- 全部走 `transform` / `opacity`，不动 `top/left/width/height`。
- `prefers-reduced-motion: reduce` 时全部归零（已有，保留）。

## 4. 组件规范

### 4.1 面板

- 底色 `--mcode-surface`，1px `--mcode-border`，圆角 `--mcode-radius-lg`。
- 顶边一道 1px 的高光（`inset 0 1px 0 rgb(255 255 255 / 4%)`），模拟光从上方来。
- 所有阴影统一从一个方向来（正上偏后），不混用多光源。

### 4.2 表格

- 表头粘顶、底色 `--mcode-surface-muted`、微字（micro 刻度）。
- 数据列右对齐 + tabular-nums。
- 行悬停：底色抬一档 + 左侧一道 2px 的信号色内嵌边。

### 4.3 标签

- **类型标签**（会话实况里的「等回答」「进行中」）：方形 `--mcode-radius-xs`，
  不是药丸——药丸是营销语汇，这里是仪表刻度。
- **严重度标签**：实心浅底 + 同色文字，保持。
- 徽标（收件箱计数）：方形、tabular 数字。

### 4.4 按钮

- 高度 32px（小号 28px），圆角 `--mcode-radius-sm`。
- 三种：主（反白）、次（描边）、文字（无框）。
- 悬停 / 按下 / 焦点 / 禁用**四种状态齐全**；禁用态降透明度并给 `not-allowed`。

### 4.5 状态页

- **加载**：骨架屏（`--mcode-skeleton`），形状跟着真实内容走，
  底下保留一行「正在加载…」的文字（读屏与「在等什么」都要说清楚）。
- **空**：一条短横线 + 一句解释，不是一大片空白。
- **错误**：就地内联，`--mcode-danger` 的左边一道实边。

### 4.6 无障碍基线

- 焦点环：2px `--mcode-accent` + 2px 偏移（保留现有做法，全站一致）。
- 页面首个可聚焦元素是**跳过导航**链接（`.skip-link`），平时藏起来，聚焦时出现在左上角。
- 所有交互元素有 `aria-label` 或可见文字（现状已达标）。

## 5. 响应式策略

| 断点 | 变化 |
|---|---|
| ≥ 1440px | 主内容 `max-width: 1440px`，侧栏 268px，信息最舒展 |
| 1180px | KPI 四列 → 两列；详情网格 → 单列堆叠 |
| 1020px | 能力库双栏 → 单栏，领域索引转为横向标签行 |
| 960px | **侧栏变顶条**：品牌 + 导航 + 开关同一行，导航项只留中文名 |
| 700px | 顶条换行；指标块压缩；对话区改全宽；提示条贴底通栏 |
| 520px | 手机档：更小的留白，指标块去掉脚注，导航项均分 |

原则：**没有信息被隐藏**。窄屏下靠横向滚动（表格）与折叠（面板）解决，
不靠「不显示」——藏起来的字段等于删掉的功能。

## 6. 桌面窗口模式

板面可以弹成独立的置顶小窗（`data-desk-mode="window"`）。

- 侧栏收起，页头标题变成**可拖动区**（`-webkit-app-region: drag`）。
- 按钮、输入框是 `no-drag`——否则点不动。
- 去掉系统标题栏就没有系统拖动区，**必须自己画一块**，否则窗口挪不动。
