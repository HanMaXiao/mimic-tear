# Agent Note

> 这套规则改编自 `deepseek-harness` 的 `.agents/notes/`，按本仓库的实际做了裁剪。裁剪了什么、为什么裁，见 [本仓库的适配](#与-deepseek-harness-的差异)。

一份 **Agent Note** 记一个影响本仓库的决策——**为什么这么定、放弃了什么**。那些代码和文档承载不了的部分，写在这里。

本文件规定 Agent Note 放在哪、什么时候写、以及[文件格式](#文件格式)。

## 布局与命名

每份 Agent Note 的路径同时编码了它的两个轴：`{生命周期}/{分类}/yyyy-mm-dd-主题.md`。

**生命周期**（顶层目录）就是它的状态，状态变了，文件在目录间移动：

- **`proposed/`** —— 提案已提出，还没实现（或只实现了一部分）。
- **`implemented/`** —— 决策已经落地。文件记录定了什么、否掉了什么，并且**与实际落地的代码保持一致**：后续代码改了路径、改了名字、改了默认值，同一次改动里把这个 note 一起改对（只改事实——路径、名字、结构——不改决策本身）。
- **`rejected/`** —— 提案被否掉了。只有当它的理由能挡住一个**看着挺有道理的错误做法**时才留着；否则整份删掉。

**分类**（嵌套目录）是决策的**种类**——见 [分类](#分类)。

文件名里的日期是这个话题**第一次被提出**的日期。跨 note 的引用用相对链接（`[话题](../../implemented/architecture/2026-…-….md)`），不用裸话、不用编号——这样链接可以被机械检查，也不会因为文件在目录间移动而失效。

活跃的生命周期树就是这份决策清单本身。不要另建一个集中的 `INDEX.md`：它重复了路径里的信息，还会让互不相干的改动挤在同一个文件上互相顶。

## 分类

每个 Agent Note 属于一个封闭的分类集合，封闭集合写在 [`scripts/verify-agent-notes.mjs`](../../scripts/verify-agent-notes.mjs) 里，门禁拒绝集合外的目录。要加一个分类，得同时改那个脚本和本节。

| 分类 | 管什么 |
| --- | --- |
| `feature` | 新的、用户或模型能感知到的能力。 |
| `bug-fix` | 修一个缺陷，或补上一个复盘暴露的缺口。 |
| `simplification` | 减掉代码、行为或表面积，但不新增能力。 |
| `architecture` | 关于**要发布的源码**的结构性决策——模块之间怎么分、运行时词汇是什么。 |
| `process` | 代码**周围**的工具、策略与流程——门禁、打包、发布纪律——不是运行时行为。 |
| `testing` | 测试基建与测试策略。 |

`architecture` 与 `process` 的分界：**architecture** 说的是我们发布的那份源码；**process** 说的是围着源码转的工具与流程。（没有 `refactor` 这一类——它和 `simplification` 重叠，而 `simplification` 的判据「可观察行为变没变」已经把它盖住了。）

## 什么时候写

只在**代码、测试和现有文档都讲不清楚**的持久决策理由上写——而且要跟改动在同一次提交里。

- 还没实现的实质性提案放 `proposed/`；已经定了的放 `implemented/`。
- 已经有一份 note 记录着这个决策，就更新那一份，不要新建重复的。
- 机械性、局部的改动免写——改个文案、调个样式、挪个文件位置，都不用写。
- 一份 note **永远不能被改成另一个决策**。要改决策就写新的一份，两份互相链接；旧的只有在满足[合并规则](#被新决策取代时)时才能删掉。

### 本仓库特别容易踩的一条

**运行时库只读、单一写路径**这类约束，`docs/specs/2026-10-20-mimic-tear-design.md` §3.3 已经写死了。规格写清楚的，不要再写一份 note 复述它。

note 的价值在规格的空白处——比如：

- 「为什么大哥的值班权限要写成可授予的状态，而不是提示词里的一句话」（spec §22 讲了结论，但取舍过程不在规格里）；
- 「为什么 `patrol-cli report` 的交班戳副作用不能靠调用方自觉」（这是代码里看不出来的坑）；
- 「为什么技能工厂的改动要同时落在三个地方」（这是跨仓库的知识）。

## 文件格式

格式由 [`scripts/verify-agent-notes.mjs`](../../scripts/verify-agent-notes.mjs) 强制执行（CI 已接上）。

### 抬头

每份 Agent Note 的前三行固定是：

```markdown
# Agent Note: <标题>

Status: <状态>
```

第 4 行是空行。`Status:` 的值只有三种，且**必须与所在目录一致**——门禁会交叉核对：

- `Status: proposed`
- `Status: implemented`
- `Status: rejected — <一行理由>`

状态行不带日期、不带括号：日期在文件名里，其余在 git 里。`rejected` 的理由是唯一带内容的状态——因为一份被否掉的 note，读者要的就是这个结论。

标题行和 `Status:` 行**保持英文**，这是机器要认的标记；正文和小节标题用中文。

### 正文骨架

每份 note 的正文以 `## 问题` 开头——动机，写的时候假设读者还不知道解法。之后的内容取决于生命周期；重复出现的小节用下面这些固定名字，中间可以插只属于这一篇的技术小节。

#### `proposed/`

```markdown
## 问题
## 提案
…本篇特有的技术小节…
## 曾考虑的替代方案
## 验收标准
## 风险
```

`## 提案` 说的是打算怎么做，可以用将来时——还没实现的阶段，方案、迁移步骤、待定问题都放这儿。`## 验收标准` 说清楚「做到什么样算做完」。`## 风险` 既写可能出问题的地方，也写这次明知会放弃什么。

#### `implemented/`

```markdown
## 问题
## 决策
…本篇特有的技术小节…
## 曾考虑的替代方案
## 后果
```

`## 决策` 用现在时描述**已经落地**的东西。`## 后果` 记录这次取舍**付了什么**和**换来了什么**。提案阶段的说法在这里是 spec 腔，门禁会拒绝：`## 提案`、`## 计划`、`## 迁移计划`、`## 验收标准` 这四个标题不允许出现在 `implemented/` 里——该折进 `## 决策`／`## 后果`／`## 验证`。

#### `rejected/`

被否掉的 note 就是冻结的提案：它保留提案时的小节（`## 验收标准`、`## 计划` 这些都留着），结论写在 `Status:` 行上。只有抬头、`## 问题`、`## 提案` 这三处，以及下面「替代方案」的强制要求对它生效。

### 曾考虑的替代方案 —— 强制

每份 note 都要有 `## 曾考虑的替代方案`：每一个真实的替代做法，以及它为什么输了。可以用 `**加粗引导**` 的段落一写一个，也可以对有争议的那个开 `### 为什么不选 X？` 小节。

**只记录真实考虑过的，不许编。** 只记下结论、没记下比过什么，invites re-litigation——这正是 note 要防的事。

### 在生命周期之间移动

移动文件就要同时改 `Status:` 行，并满足目标目录的骨架要求，否则门禁不过。具体地：

- `proposed/` → `implemented/`：把 `## 提案` 改写成现在时的 `## 决策`，把 `## 验收标准` 和 `## 风险` 折进 `## 后果`（或者折成现在时的 `## 验证`，用来钉住现在的行为），删掉计划类的说法。
- `proposed/` → `rejected/`：只加理由，然后冻结。

### 归档与删除

一份 `implemented/` note 如果只剩「小改动」或纯机械改动的记录，删掉它（中文与正文一起删），并修好指向它的链接。本地 bug 修复、性能改动、新能力、有实质的行为或归属决策，**不因为实现得小就够格删掉**。

其余的 `implemented/` note，在「决策已经完整、理由不太可能再指导后续工作、但记录本身仍有历史价值」时归档到 `archived/{分类}/`。归档动作本身只能是：移动文件、在 `Status: implemented` 下面插入一行 `Archived: YYYY-MM-DD`、修好入链。归档之后**永久冻结**——不编辑、不翻译、不重排、不删除，也不拿它当当前行为的依据。

`proposed/` 的 note **不归档**：不再值得做，就诚实地否掉它，走 `rejected/` 的格式。

## 与 deepseek-harness 的差异

`deepseek-harness` 的同一套机制有三条本仓库不需要，砍掉它们是刻意的：

| deepseek-harness | 本仓库 | 为什么 |
| --- | --- | --- |
| 每份 note 一份英文 + 一份 `.zh.md` + 一份 `.i18n.yaml` 侧车，记录双语配对哈希 | **单语**，正文即中文 | 本仓库的文档、代码注释、README 全是中文，从来没有双语配对的习惯。侧车和配对门禁要维护两倍的内容，换不来任何东西。 |
| `scripts/` 下用 TypeScript + Vitest 写门禁 | **纯 Node 内置模块**的 `.mjs` | 本仓库零第三方依赖，装不了 Vitest；现有三个守卫脚本都是这个形态，门禁要跟它们同构才不突兀。 |
| 归档用「封存清单 + 逐文件哈希」锁住不可变性 | 归档只加一行 `Archived:` 日期 | 那边有 1800 多份 note，才需要哈希级防篡改。本仓库现在个位数，等真的攒到需要的那天再加。 |

保留的部分：生命周期 × 分类的封闭集合、路径编码状态、`Status:` 与目录交叉核对、强制记录替代方案、`implemented/` 禁止提案腔标题、归档冻结。
