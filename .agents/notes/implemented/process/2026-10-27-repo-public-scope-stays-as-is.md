# Agent Note: 仓库公开范围按现状保持，不做脱敏也不重写历史

Status: implemented

## 问题

这个仓库是**公开的**：`https://github.com/HanMaXiao/mimic-tear`。

公开之前做过一次盘点，`docs/` 下的内容带着若干本机痕迹：

| 类别 | 数量 | 性质 |
| --- | --- | --- |
| 本机会话 id | 44 处 | 本机运行时标识符 |
| 含用户名的绝对路径 | 5 处 | 本机文件系统路径 |
| 本机项目路径 | 3 处 | 本机目录 |
| 其它项目名 | 36 处 | 别的项目的名字 |
| **凭据类** | **0 处** | —— |

这批东西**已经在公开历史里了**。问题于是变成：现在该怎么办。

## 决策

**保持现状。不脱敏，不重写历史。**

理由按重要性排：

1. **凭据泄露 0 处。** 盘点过的是会话 id、绝对路径、项目名——**没有一个能换来权限**。会话 id 是本机运行时标识符，拿到它也进不了别人的会话。
2. **已经公开了。** 这些内容在公开历史里，事后脱敏只清掉 HEAD 版本，历史里的副本照样在。**代价是全量重写历史**（force push、重新 clone、重新发 tag、所有人重新拉），而收益是零——因为底层事实没有泄露。
3. **大老板已经拍板。** 2026-10-27 明确按「保持现状」处理。

`Saved/` 从未被 track（`.gitignore` 已排除 `Saved/`），**不在公开范围**。

## 曾考虑的替代方案

**脱敏 `docs/` 里的会话 id 与绝对路径，改写历史。** 一次性把公开历史清干净。放弃的理由：**上面第 2 条**——已经公开的内容不因事后清理而消失，而 force push 会毁掉所有 fork 和 clone 的协作基础，还要重发 tag。**代价极高，收益是零**（凭据泄露本来就是 0）。

**把 `docs/` 整体改成公开前的样子（去掉本机痕迹），只改 HEAD 不改历史。** 成本低一些。放弃的理由：这是**一半的修复**——历史里还在，而 HEAD 里突然少了几十处引用会让文档读起来缺上下文（比如「见 `mvs_xxx` 会话」变成「见某次会话」）。**为了让一个已经解决的问题看起来像被解决了，代价是文档变难读。**

**把 `docs/` 整目录移出仓库（挪进私有仓库或本机）。** 放弃的理由：规格和计划是**这个产品的知识**，公开仓库的价值之一就是它们在。移走之后 clone 的人拿不到任何上下文，比公开着多几处无害痕迹更糟。

**接受公开，但把本机痕迹从此不再写进 `docs/`。** 这是**唯一被采纳的部分**——从今往后写文档时，例子用占位符或仓库相对路径，而不是真会话 id 和真绝对路径。

## 后果

**换来的**：仓库保持可读、可贡献、无历史包袱。`docs/` 里的规格和计划对 clone 的人直接可用。

**付掉的**：

- **公开历史里有 44 处会话 id、5 处含用户名的绝对路径、3 处本机项目路径、36 处别的项目名。** 认了。它们不换权限，但确实让公开历史不完全「干净」。
- **「从今往后不再写本机痕迹」靠自觉**，没有守卫脚本检查 `docs/`——`check-package.mjs` 和 `check-style.mjs` 只扫包目录（`miniapps/mimic-tear/`），`docs/` 在包目录之外。`check-style.mjs` 的第 5 条（源码里没有烤进构建机的绝对路径）同理只覆盖包内。
- **`Saved/` 与 `.ai-advice/` 不在仓库里**，所以它们的本机痕迹不构成泄露——但也意味着**那两处的知识不进版本控制**，仓库外的协作拿不到。

**不做的事**：不重写历史；不脱敏 `docs/`；不把 `docs/` 移出仓库；不为此新增守卫脚本。
