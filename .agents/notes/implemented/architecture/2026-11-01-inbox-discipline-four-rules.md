# Agent Note: 收件箱的四条纪律各自只管一件事

Status: implemented

## 问题

大哥的收件箱在 2026-10-30 长到 100 条结论、93 条未确认。四件事同时压在上面，而且它们**互相看着对方**：

| 事 | 现状 | 谁在管 |
| --- | --- | --- |
| 桌面上该有几条「需要你拍板」的结论 | 没有上界，堆到 93 条 | 收件箱装配 |
| 大哥重复报同一件事 | 重复占位置，只能靠大哥自觉 | 入账那一层 |
| 一条结论能有多长 | 100 词这件事只存在于文章里 | 无人管 |
| 93 条历史结论怎么办 | 留着，或删掉 | 无人管 |

这四件事如果各写一份判定，就会出现「徽标说 3 条、列表里 2 条」这种老账（见 [`inbox-builder.mjs`](../../../../miniapps/mimic-tear/miniapp/node/inbox-builder.mjs) 顶上那段注释）。所以它们必须**只有一份实现**，而且彼此的边界要说清楚：**哪一条纪律管哪一层**。

更要紧的是两个方向相反的要求同时成立：

- 超上界的新结论**不许丢**（结论里有大老板当时没来得及看的信息）；
- 收件箱**必须有**结构性的上界（不然它只是「等人来清」）。

## 决策

四条纪律各管一层，互不越界。判定的**纯函数**都在新模块 `miniapps/mimic-tear/miniapp/node/patrol-rules.mjs` 里，写路径、收件箱装配、CLI 共用这一份。

### 上界：桌面名额先来先服务，账本一条不少

上界是 `patrol-config.json` 里的 `deskLimit`（默认 20），只约束**需要拍板**的结论（`severity !== 'low'` 且未确认）——口径与 `selectAttentionItems` 完全一致。运行时产生的收件箱项（问卷 / goal-paused / session-error / plan-blocked）**不受**这个上界约束：那不是大哥能控制的东西。

名额按**到达顺序**排：先到的先占位，后来的记进账本并标成 `onDesk: false`。收件箱只装配 `onDesk` 的那些，但账本（`patrol.json`）里一条不少。

### 合并：键只有「项目:严重度」，只合并未确认的

入账那一层（`PatrolStore.add()`）按 `${projectName ?? projectId}:${severity}` 找同键且**未确认**的结论，命中就并进去：内容（标题 / 正文 / 备注）换成新的，加上 `updatedAt`，身份（`id` / `createdAt` / 来源）留着。

已确认的结论**不参与合并**：确认过的问题又冒出来，那是新的一件事。

合并放在 store 而不是 CLI 或巡检那两条路径上，是为了让它成为**结构性保证**：两条写路径自动都享有去重，不靠调用方自觉。

### 带宽：只量正文，超限在入账层抛错

单条结论的正文 ≤ 100 词（中文按字、英文按空白分词，两者相加）。超限**抛错**，错误信息说清超了多少、上限多少。

只量**正文**，不量标题：两条写路径的标题各自截断（CLI 120 字、巡检 60 字），量进去等于让一条 60 字的摘要把额度吃掉两遍。

看门狗那条线自己装得下：`watchdog-alerts.mjs` 的 `fitToBoardBudget()` 按优先级一行一行地装，装不下的不装，并说明剩下的证据去哪儿看。告警日志里留着**完整**的那一份——日志是主渠道，板面那份是给人看的。

### 归档：搬家，不是销毁

`patrol-cli archive "<理由>"` 把账上的结论搬进 `patrol-archive.json`，并记下元数据（什么时候、谁、为什么、多少条）。**先写归档账，再清账本**——归档写不进去时账本原封不动。

已归档的结论**仍然进 `alreadyReported`**：它们不在账本上了，但「报过了」这件事没变。少了这一条，大哥会把同一个问题再报一遍——那正是收件箱堆到 93 条的原因之一。

### 技能匹配：次序必须确定

派工时按派工内容的关键词匹配技能库，命中就记一次 `use`。匹配的排序从「分数 + 最近用过」改成「分数 + 技能名 + id」：原来那种排序让**同样的输入**在用过之后和没用过的时候命中不同的技能，于是「派工命中哪个技能」变成了一个会漂移的问题。

## 曾考虑的替代方案

**上界按「最新优先」占位，挤掉最旧的。** 放弃的理由：挤掉最旧的等于**删结论**——主规格 §19.5 已经确立了「撤回过的结论仍然留着」，同理，被别的结论挤掉的结论也应该还找得到。先来先服务让「超界时新结论不占桌面」成立，同时一条都不丢。

**超上界的结论直接丢弃，不进账本。** 放弃的理由：那就是「丢了」。大哥报过的事必须在 `alreadyReported` 里看得见，否则会重复报。

**合并键再加上来源、标题或时间窗。** 放弃的理由：键越细，去重越弱，「同一个问题」就不再是一个确定的事实。键粗一点会误合并（值班结论和看板结论同项目同严重度会并成一条），但那正是上界与带宽要解决的量级问题。

**超限的结论截断后入账。** 放弃的理由：截断会把大哥的话改掉，而大哥需要知道自己写超了。

**看门狗的告警豁免带宽纪律。** 放弃的理由：豁免等于没有纪律——板面结论就是板面结论。替代方案是让看门狗自己装进预算（`fitToBoardBudget`），代价是板面那份正文可能比日志里那份短。

**归档 = 删除，或者归档后从 `alreadyReported` 里拿掉。** 放弃的理由：前者丢信息，后者让大哥重复报同一个问题——两者都把「归档」变成了另一种形式的丢。

**技能匹配按「最近用过」排序。** 放弃的理由：匹配结果依赖历史，同样的输入给出不同的结果，测试就没法钉住它。

## 后果

**换来的**：收件箱的条数有**结构性**上界（不是靠人工清历史），同一件事只占一格，单条结论有可测的带宽上限，93 条历史结论退场但一条不少且可查，技能注册表的 `usageCount` 第一次会动。

**付掉的**：

- **合并键很粗**：同项目同严重度的两条不同结论会并成一条。值班结论与看板结论同项目同严重度时会互相覆盖内容。这是「一个项目一个严重度只占一格」的代价。
- **看门狗的板面正文可能被装短**：正文超过 100 词时，板面那份按优先级截到预算内，完整证据在 `watchdog-alert.log` 里。
- **既有测试改了四处**：`tests/duty-stamp.test.mjs`（同一份报告连报两次现在是**一条**）、`tests/project-service.test.mjs`（值班结论换成 `low`，好让三条结论各占一格）、`tests/watchdog-board.test.mjs`（新状态并进同一条，断言改为「板面看到的是新内容」）。三处都是**新规则直接改变了断言对象**，不是把红线改绿。
- **老数据不受新规则追溯**：归档前 100 条里有 97 条正文超过 100 词。新规则只作用在**新入账**的结论上。
- **`setConfig` 不再把没传的字段写成默认值**：`undefined` 会被 `Boolean(undefined)` 变成 `false`，那是一次没人要求的改动（以前 `POST /api/patrol/config` 只改桌面上界就会顺手关掉巡检开关）。
