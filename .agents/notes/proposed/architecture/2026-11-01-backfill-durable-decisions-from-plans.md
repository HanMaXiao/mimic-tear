# Agent Note: 把 `docs/plans/` 里的持久决策回填成 Agent Note

Status: proposed

## 问题

`.agents/notes/` 这套机制在 2026-11-01 立起来的时候，只带了几份 note。仓库里还有一批**已经在 `docs/plans/` 里躺着、但从没被提炼成决策记录**的东西。

最明显的两份：

**`docs/plans/2026-10-22-line-ownership.md` —— 两条线的分工与提交边界。**

这份文件记的是两件事：

1. **文件归属表** —— 看板客户端的视觉与交互归 UI/UX 线，运行时、值班、看门狗、派工归负责人线；以及四道「接缝」（A：API 载荷形状；B：问题卡的会话绑定；C：共享规格文件；D：发布单元）。
2. **提交纪律** —— 这个仓库里**不许用会扫全树的提交方式**。`git add -A` / `git add .` / `git commit -a` 是错的，因为它会把**别人写到一半的在制品**一起卷进同一个 commit。只允许两种形式：**路径限定**（`git commit -F <msg> -- <path...>`）和**补丁快照**（`git diff --output=<patch> -- <shared>` → `git apply --cached <patch>` → `git diff --cached` → `git commit -F <msg>` → `git show --stat HEAD`）。

提交纪律已经被 `scripts/install-hooks.mjs` 做成了本机 `pre-commit` 钩子（范围规则 + 在制品规则），但**钩子默认不装、故意 fail-open、且不在 CI 里**。也就是说：这条纪律的**道理**只存在于那份计划文档里，仓库里没有任何地方说明**为什么**它必须这么严。

**`docs/plans/2026-10-26-watchdog-trigger-schedule.md` —— 看门狗的生命周期：跟着 MiniMax 走。**

记的是「为什么终端会闪一下就关掉」这个真问题的四个修法：一次性执行 + 自我重武装、隐藏启动（`wscript.exe`）、宿主死了就禁用、交接时唤醒。

这两份都有同一个毛病：**它们是「一次执行发生了什么」的记录格式**——有日期、有上下文、有当时的判断。里面那些**决定**被埋在流水账里，没有被提炼成「决定 + 理由 + 放弃了什么」的形式。于是：

- 想知道「为什么不能 `git add -A`」的人，得读完一整份计划，而不是读一条决策；
- 决策**被后续修订时**，没有机制提醒「原来那条决策记录要跟着改」——因为它根本不是一条决策记录；
- 替代方案没被保留下来。当时为什么否掉别的做法，只有原文里的一句话，而那篇文档随时可能被当成历史归档。

## 提案

把 `docs/plans/` 里**已经是决定、且理由仍在指导后续工作**的部分，提炼成 `.agents/notes/implemented/` 下的 Agent Note。

**范围（第一批，两份）：**

1. `implemented/process/2026-11-01-path-limited-commits-and-shared-worktrees.md`
   —— 来源：`docs/plans/2026-10-22-line-ownership.md` §3 提交纪律 + §1 文件归属。
   内容：为什么禁全树提交（会吞掉别人的在制品）、两种允许的提交形式、本机钩子的边界（默认不装、fail-open、CI 上查不了）。

2. `implemented/architecture/2026-11-01-watchdog-lifecycle-follows-minimax.md`
   —— 来源：`docs/plans/2026-10-26-watchdog-trigger-schedule.md` + `docs/plans/2026-10-22-watchdog-gap-plan.md`。
   内容：看门狗的触发节奏为什么跟着宿主走、一次性执行 + 自我重武装、隐藏启动、宿主死了就禁用。

**做法：**

- **原文件不动。** `docs/plans/` 是历史记录，保持冻结；note 是提炼出来的决策记录。两者交叉链接。
- **只提炼「决定」，不搬流水账。** note 里不出现「当时我们做了什么」「第一批做了什么」，只出现「定了什么、为什么、放弃了什么」。
- **每份 note 都要补 `## 曾考虑的替代方案`。** 这是主要工作量——原文里通常只留了选中的那条路。
- **两份 note 都要标清哪些部分还没沉淀。** 比如提交纪律的**接缝清单**（A/B/C/D）目前散在原文里、还没进 note。

**不在范围内：**

- `docs/specs/` —— 规格记事实与原则，不是决策记录，**不动**。
- `docs/2026-10-28-optimization-recommendations*.md` —— 那是建议清单，不是决定。
- `docs/2026-10-30-board-redesign.md` —— 视觉规范，是规格类文档，留在 `docs/`。
- `docs/plans/2026-10-22-mimic-tear-resume-plan.md` —— 一次性续跑方案，当时拍完就执行完了，没有留待指导后续工作的决定。

## 曾考虑的替代方案

**把 `docs/plans/` 的文件整体改写成 note 格式。** 一份文档一个去处，不用维护两边。放弃的理由：**计划文档和决策记录不是一回事**。计划记的是「这轮怎么切分、做到哪、踩了什么坑」，note 记的是「这个决定为什么这么定」。一份 46 KB 的实施计划里，真正属于决策记录的也许只有三段——为三段重排整份文档，会把「执行历史」这个功能也毁掉。

**不回填，让未来的 note 只往前写。** 零成本。放弃的理由：**旧决策会一直以「计划文档」的形式存在**，读者找不到，也得不到「为什么」这一层。而且回填能顺带把「为什么不能 `git add -A`」这条**纪律的理由**补上——现在它只有一条规矩，没有道理。

**把回填做成一条机械的流程：每次改 `docs/plans/` 就同步一份 note。** 放弃的理由：**大多数计划文档没有对应的持久决策**（见「不在范围内」那份续跑方案）。无差别地要求同步，会产出一堆「implemented 但没有决定」的 note——那比不回填更糟，因为它让人以为这里有决策。

**只回填提交纪律这一份，看门狗那部分等下次改到再说。** 放弃的理由：看门狗那部分**已经踩过坑了**（终端闪一下就关掉、`ERROR: Access is denied.`），坑的记录还在计划文档里，而决策本身还没沉淀。它的紧急度和提交纪律一样高。

**回填之后删掉 `docs/plans/` 的对应段落。** 避免两处并存。放弃的理由：计划文档是**执行历史**，删掉就丢了「当时做了什么」的上下文；而 note 里的决策**不该带时间线**。两者并存、互相链接，各管一段。

## 验收标准

做完这一批，下面每一条都必须成立：

1. `.agents/notes/implemented/process/` 下有一份提交纪律的 note，`.agents/notes/implemented/architecture/` 下有一份看门狗生命周期的 note。
2. 两份 note 都含 `## 问题`、`## 决策`、`## 曾考虑的替代方案`、`## 后果`，且 `## 曾考虑的替代方案` 里每一条都是**真实考虑过**的（能指回原文或 git 历史），不是编的。
3. 两份 note 都**没有**流水账内容——通篇没有「第一批」「当时做到哪一步」这类表述。
4. 两份 note 都有指向 `docs/plans/` 原文的相对链接；原文**一字未改**。
5. `node scripts/verify-agent-notes.mjs` 通过。
6. `node --test` 仍全绿，且 CI 的四步守卫全绿——回填不该影响任何运行时行为（这次改动**只碰 `.agents/`**，一个运行时文件都不改）。

## 风险

- **改写历史的风险。** 把决策从流水账里「提炼」出来，天然带一层主观判断。提炼者理解偏了，note 就把当时的决定记歪了。**缓解**：每条决策都指回原文的具体位置，读者可以核对；替代方案只写能指回依据的。
- **重复记录的风险。** 同一件事可能在 `docs/specs/` 和 `docs/plans/` 里都出现，被提炼两次。**缓解**：每份 note 写明它的来源是 plans 而不是 specs，并在边界处交叉链接——但「哪一条只存在于 specs」仍然要人工判断。
- **范围蔓延的风险。** `docs/plans/` 里有 5 份文件、约 100 KB。第一批做完很容易顺手把剩下三份也做了。**缓解**：范围明确限定两份，剩下三份各自的去留留到下一次决定。
- **无替代方案可写的风险。** 如果某条决策当时**根本没考虑过别的做法**，那 `## 曾考虑的替代方案` 就会是空的——而它是强制小节。**缓解**：门禁会挡住这种情况，那时正确的做法是回到原文和 git 历史去考古，而不是编一条。**这一条是真风险**：门禁的强制会逼人填内容，而填内容的最省事方式就是编。
- **与「implemented 要跟代码保持一致」冲突的风险。** 提交纪律的 note 提到 `install-hooks.mjs`，看门狗的 note 提到好几个 `.mjs` 文件。这些路径以后会变，note 得跟着改——而 note 在仓库里、代码在仓库里，改起来是同一次提交的事，不构成额外负担。
