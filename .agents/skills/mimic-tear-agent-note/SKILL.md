# 写一条 Agent Note

一份 Agent Note 记**为什么这么定、放弃了什么**——那些代码、测试和现有文档都讲不清楚的部分。格式规范在 [`.agents/notes/README.md`](../../notes/README.md)，这里是动手时的判断。

## 先问：这条该写吗

只有**持久决策的理由**才写。判据是「代码、测试、现有文档能不能替我回答这个问题」。

**免写**（写下来只是增加维护负担）：

- 改文案、调样式、挪文件位置；
- 修一个局部 bug，行为改动的理由一眼可见；
- 规格里已经写死的约束——运行时库只读、单一写路径、四层架构、21 条 API 路由、12 种 SSE 事件。**规格是事实的权威，note 是理由的权威。**

**该写**：

- 一个决定影响了别处的做法，光看代码看不出来为什么；
- 一个坑踩过、代价很大，而坑的成因不在代码注释里；
- 一套机制跨了几个地方，改的时候必须一起改，而「为什么必须一起改」只存在于某个人脑子里。

拿不准就先查 `.agents/notes/` 有没有相关的旧记录——**更新那一份，不要新建重复的**。

## 放哪个分类

| 分类 | 判据 |
| --- | --- |
| `architecture` | 关于**要发布的源码**的结构性决策：模块怎么分、归属在哪、什么不许动 |
| `process` | 代码**周围**的工具、策略与流程：门禁、打包、发布纪律、协作纪律 |
| `feature` | 新增用户或模型能感知到的能力 |
| `bug-fix` | 修缺陷，或补上复盘暴露的缺口 |
| `simplification` | 减掉东西但不新增能力 |
| `testing` | 测试基建与测试策略 |

`architecture` 与 `process` 的分界：**说的是发布的那份源码，还是围着它转的流程。**

## 生命周期

| 目录 | `Status:` | 什么时候在 |
| --- | --- | --- |
| `proposed/` | `Status: proposed` | 决定了要做，还没做 |
| `implemented/` | `Status: implemented` | 已经落地，文件与代码保持一致 |
| `rejected/` | `Status: rejected — <一行理由>` | 想过，否了 |
| `archived/` | `Status: implemented` + 下面一行 `Archived: YYYY-MM-DD` | 冻结的历史快照 |

**决定了不做就诚实地否掉，不要让它烂在 `proposed/`。** 长期挂着的提案会让人以为还有人在等它。

## 骨架

```markdown
# Agent Note: <标题>

Status: <状态>

## 问题

<动机，写的时候假设读者还不知道解法>

## 决策

<现在时描述已经落地的样子>

## 曾考虑的替代方案

**<别的做法。** <它为什么输>

## 后果

<这次取舍付了什么、换来了什么>
```

`proposed/` 的骨架换成 `## 提案` / `## 曾考虑的替代方案` / `## 验收标准` / `## 风险`；`rejected/` 保留提案时的小节，只在 `Status:` 行上写结论。

**`## 曾考虑的替代方案` 是强制的**，门禁会挡。只记结论不记比过什么，等于给后人重新翻案的机会。

**只写真实考虑过的。** 实在考古不出来，回到原文和 git 历史去找；实在没有，就说明当时就是这么定的，别编。

## 写完过门禁

```sh
node scripts/verify-agent-notes.mjs
```

它会挡：分类目录不在封闭集合、文件名缺日期、`Status:` 与所在目录不一致、第一个小节不是 `## 问题`、缺必带小节、`implemented/` 里出现提案腔标题、缺「曾考虑的替代方案」、归档件缺 `Archived:` 行。

## 落地之后

**改了路径、名字、默认值、机制，就在同一次改动里把 note 改对。** 只改事实，不改决策——推翻决策要写新的一份并互链。

## 别做的事

- 别把规格的内容抄进 note；
- 别建 `docs/adr/`——决策记录只有一个家，就是 `.agents/notes/`，门禁会挡；
- 别在一份 note 里塞流水账（「当时先做了 A，后来改成 B」）——那是 `docs/plans/` 的活；
- 别为了凑格式编替代方案。
